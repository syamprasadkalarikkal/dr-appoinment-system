College Project Presentation

AMRT Healthcare
Appointment System

A full-stack, role-based digital healthcare platform featuring AI symptom analysis, real-time doctor–patient chat, and seamless appointment management.

Next.js 14  ·  Supabase  ·  WebSocket  ·  Tailwind CSS
Problem Statement

Why This System Is Needed

🏥

Fragmented Healthcare Access

Patients struggle to find the right specialist quickly, leading to delayed diagnosis and treatment.

📞

Inefficient Appointment Booking

Traditional phone-based booking wastes time for both doctors and patients with no real-time availability.

💬

No Secure Communication Channel

After booking, patients have no safe, direct channel to consult their assigned doctor digitally.

🔍

Lack of Preliminary Guidance

Patients visit clinics for minor issues due to no pre-assessment tool to judge urgency.

Objective

What We Built

🎯

Unified Healthcare Portal

A single web platform where patients book appointments, doctors manage schedules, and admins oversee the entire ecosystem in their dedicated dashboards.

🤖

AI-Powered Symptom Checker

Patients describe symptoms to an intelligent AI assistant that provides preliminary assessment and urgency guidance before booking.

⚡

Real-Time Doctor–Patient Communication

After appointment confirmation, a secure WebSocket chat room opens between the doctor and patient for direct digital consultation.

TablePurpose

Security

Core Module

Real-Time Chat System

How It Works

  • 1. Patient books appointment
  • 2. Doctor confirms → chat unlocked
  • 3. Both connect to WebSocket server
  • 4. Deterministic room ID generated
  • 5. Messages persisted to Supabase
  • 6. Read receipts & presence events broadcast
🔒

Appointment-Gated

Chat only unlocks after a doctor confirms. Verified on every message.

⚡

WebSocket Events

join · message · typing · read_receipt · presence

💾

Persistent History

All messages stored in Supabase messages table for later retrieval.

Security

Data Protection & Access Control

🛡️

Row-Level Security (RLS)

Supabase RLS policies ensure users can only access their own data at the database level.

🔑

Middleware Route Guard

Next.js middleware checks user role from localStorage before rendering any dashboard.

🚪

Chat Gating

WebSocket server verifies a confirmed appointment exists before allowing any chat message.

🔐

Supabase Auth

Email/password authentication managed by Supabase Auth with JWT tokens.

🏥

Doctor Verification

Doctors must be approved by Admin before they appear to patients or can receive bookings.

🔒

Environment Variables

Supabase keys stored securely in .env.local, never exposed to the client for service-role operations.
